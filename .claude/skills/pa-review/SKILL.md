# PA 복습 자료 생성

## When to use

사용자가 `class-note/{{날짜}}` 폴더의 강의를 복습하고 싶다고 하거나, "복습 자료 만들어줘", "오늘 강의 정리해줘" 처럼 특정 날짜 폴더를 지정할 때 사용한다. 이 폴더에는 그날 진행된 강의 슬라이드(PDF, 파일명이 `N강. 제목.pdf` 형식)와 사용자가 수업 중 남긴 파편적인 필기(md 파일, 파일명은 `노트.md`)가 들어있다.

## Workflow

1. **대상 폴더 확인**: 사용자가 날짜를 주면 `class-note/{{날짜}}`를 대상으로 한다. **`{{날짜}}`는 항상 실제 폴더명을 그대로 쓴다** (예: 폴더명이 `080426`이면 문서 제목·파일명도 `080426`으로 쓴다. `08-04-2026`처럼 다른 형식으로 재포맷하지 않는다). 날짜를 안 주면 폴더 목록을 보여주고 물어본다.
2. **폴더 스캔**: 대상 폴더 안의 `*.pdf`(강의 슬라이드)와 `*.md`(필기, 이미 생성된 `{{날짜}}리뷰.md`는 제외) 파일을 모두 나열한다.
3. **PDF 읽기**: 각 PDF를 Read 도구로 전체 읽어서 강의별 핵심 개념·정의·구조를 요약한다. 파일명의 `N강. 제목`을 그대로 강의 제목/순번으로 사용한다.
4. **필기 읽기 및 확장**: md 필기 파일(들)을 읽는다. 필기는 단어·문장 파편 수준으로 끊겨 있을 수 있으니, `## N강`, `### 소제목` 같은 헤더나 문맥으로 어느 강의에 속하는지 판단해 강의별로 재배치한다. 각 파편을 PDF 슬라이드의 맥락과 대조해 무슨 뜻인지 풀어쓰고, 생략된 주어·이유·배경을 보완해 완전한 문장/설명으로 확장한다. 원문 그대로 옮기지 말고, 슬라이드에 없는 사용자 고유의 이해나 실무 팁이 있으면 그 관점을 살려서 서술한다.
5. **퀴즈(오늘의 퀘스트 Q&A) 처리**: 필기 파일 끝에 퀴즈 문답이 있으면(문항/선택지/정답·오답/해설 형태), 정답과 해설만 뽑아 "핵심 확인 문제" 형태로 간결하게 정리한다. 오답으로 표시된 문항도 정답과 해설은 그대로 살린다.
6. **복습 문제 10개 출제**: 노트에 있던 퀴즈와는 별개로, PDF+필기 내용을 바탕으로 그날 배운 개념을 확인하는 새 문제를 10개 직접 출제한다. 객관식/단답형을 섞어도 되고, 슬라이드를 그대로 베낀 문제가 아니라 개념의 이해·적용을 묻는 문제로 만든다. 강의가 여러 개면 강의별로 배분한다. **이 10문제는 정답·해설 없이 문제만 적는다** — 사용자가 스스로 풀어보는 용도이므로 "핵심 확인 문제" 섹션과 달리 답을 공개하지 않는다.
7. **병합·재구성**: 강의별로 PDF 요약과 확장한 필기를 "핵심 개념"이라는 하나의 섹션으로 합친다 — 슬라이드 내용과 필기 내용을 분리하지 않고, 필기에서 나온 포인트를 관련 개념 설명 안에 자연스럽게 녹여 하나의 흐름으로 서술한다. 슬라이드를 그대로 베끼지 말고, 필기에서 사용자가 강조한 부분(직접 겪은 예시, 실무 팁, 스스로 정리한 비유 등)을 우선순위에 반영해 "왜 중요한지"가 드러나게 쓴다. 여기에 정리된 퀴즈("핵심 확인 문제")와 새 복습 문제 10개를 강의 순서(0강, 1강, 2강 ...)대로 이어붙여 하나의 복습 문서를 완성한다.
8. **저장**: 결과를 `class-note/{{날짜}}/{{날짜}}리뷰.md`로 저장한다. 이미 파일이 있으면 덮어쓰기 전에 사용자에게 확인한다.
9. **검증**: 저장 후 다시 읽어서 강의 번호 누락, 빈 섹션이 없는지, 복습 문제가 정확히 10개인지 확인한다.

## Output format

```markdown
#{{날짜}} PA 복습

## N강. 강의 제목

### 핵심 개념
(슬라이드 내용 + 확장한 필기를 하나로 섞어서 서술. 파편적 필기도 완전한 설명으로 풀어서 녹인다)

## 핵심 확인 문제

| # | 문제 | 정답 | 해설 |
|---|---|---|---|
| 1 | ... | **...** | ... |
(노트의 문항 수만큼)

## 복습 문제 10선
1. 문제 (정답·해설 없음)
(총 10문항, 번호 목록 — 표 아님)
```

강의마다 슬라이드 요약과 필기를 분리하지 않고 하나의 "핵심 개념" 서술로 합친다. 필기 파편은 문장으로 확장해서 자연스럽게 섞되, 슬라이드에 없던 사용자 고유의 통찰이나 예시는 문맥상 티가 나도록 녹여 쓴다.

### 가독성 — 마크다운을 적극 활용한다

밋밋한 불릿 나열로 끝내지 말고, 내용 성격에 맞는 마크다운 요소를 골라 쓴다.

- **표**: 비교 대상이 여러 개고 속성이 겹치면 문장으로 풀지 말고 표로 정리한다.
- **인용문(`>`)**: 강의의 "핵심 원칙"·"주의" 같은 한 문장 요약은 인용 블록으로 꺼내 눈에 띄게 한다.
- **코드 블록**: 명령어·경로·설정 파일 예시는 인라인 코드나 코드 블록으로 감싼다.
- **중첩 불릿·굵게**: 개념 아래 근거·예시는 하위 불릿으로 한 단계 내리고, 핵심 용어는 굵게 표시한다.
- **구분선(`---`)**: 강의가 여러 개면 강의 사이에 구분선을 넣어 스크롤할 때 경계가 분명하도록 한다.
- 남용은 금지 — 표로 쓸 만큼 구조화되지 않은 서술형 설명까지 억지로 표에 넣지 않는다. 글의 성격에 맞는 형식을 고른다.
- **간결하게**: 필기를 확장한다고 문장을 길게 늘어뜨리지 않는다. 한 문장에 담을 수 있는 이유·배경은 한 문장으로 끝내고, 같은 말을 두 번 하지 않는다. 핵심 개념은 완전한 문장이되 군더더기 없이, 비교 대상은 표로 압축한다.

## Notes

- 필기 파일명은 폴더마다 다르므로 이름으로 필터링하지 말고 해당 폴더의 모든 `.md`를 후보로 본다.
- PDF가 여러 개면 파일명 앞자리 숫자(0강, 1강, 2강 ...) 순서로 정렬해서 처리한다.
- 필기가 매우 단편적이라 강의 귀속이 애매한 줄은 가장 가까운 앞쪽 헤더의 강의에 붙인다.
- **Output format은 예시가 아니라 규격이다.** 표로 적으라고 되어 있으면 표로, 목록으로 적으라고 되어 있으면 목록으로 — 실행마다 다르게 재해석하지 않는다.
