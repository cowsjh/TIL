## MCU — 컴퓨터 한 대를 칩 하나에 넣은 것

**MCU**(Microcontroller Unit)는 CPU·Flash·SRAM·주변장치를 실리콘 다이 하나에 담은 컴퓨터다. 전자레인지의 버튼 입력·시간 표시·마그네트론 On/Off를 전부 처리하는 칩 하나가 MCU고, SO-101의 서보 안에도 하나씩 들어 있다 — 통신으로 목표 각도를 받고, 내부 포텐쇼미터를 읽고, PID를 돌려 모터에 PWM을 주는 일을 1kHz로 반복하는 게 라즈베리파이가 아니라 그 작은 칩이다.

이름은 두 조각으로 나뉜다.

- **micro** — 1971년 Intel 4004(최초의 마이크로프로세서)에서 온 말. 그 전 컴퓨터의 CPU는 기판 여러 장짜리였고, 마이크로미터 공정으로 칩 하나에 넣었다는 뜻이다.
- **controller** — 마이크로프로세서는 CPU만 있는 반쪽이라 RAM·ROM·I/O 칩을 따로 붙여야 했다. 1971년 TI TMS1000이 그걸 한 칩에 담았고, 용도가 범용 계산이 아니라 기계 **제어**라서 processor 대신 controller가 됐다.

### MCU · 마이크로프로세서 · SBC

| 구분 | 들어 있는 것 | 예 | OS |
|---|---|---|---|
| 마이크로프로세서(CPU) | 연산 코어만 | Intel i7 | 필요 |
| **MCU** | CPU+Flash+SRAM+주변장치 | STM32, ATmega, ESP32 | 없음(bare-metal) 또는 RTOS |
| SBC | SoC+DRAM+저장장치 기판 | 라즈베리파이, Jetson | 리눅스 |

아두이노 우노는 ATmega328P라는 MCU 한 개에 편한 보드를 씌운 것이다.

### 제어를 MCU가 맡는 이유 — 속도가 아니라 약속

리눅스가 못 하는 건 속도가 아니다. `time.sleep(0.001)`은 평균 1ms지만 가끔 8ms이고, 제어 루프에서 $\Delta t$ 가 흔들리면 이산 PID의 적분·미분 항이 그대로 틀어진다. MCU에서는 그럴 일이 없다.

1. **스케줄러가 없다** — 내 코드에서 CPU를 뺏어갈 프로세스 자체가 존재하지 않는다.
2. **인터럽트가 하드웨어 배선이다** — 타이머 신호가 오면 NVIC가 CPU를 강제로 ISR로 점프시킨다. 소프트웨어 판단이 끼어들지 않아 지연이 항상 143ns 근처(84MHz, 진입 12사이클).
3. **코드가 Flash에서 직접 실행된다** — 가상 메모리·페이지 폴트·스왑이 없다.

이 "항상 같은 시간에 반응한다"가 **결정적(deterministic)**이고, Hard 실시간의 정체다. 빠른 것과는 다르다 — 라즈베리파이는 클럭이 20배 빠른데도 제어 루프를 못 맡는다.

## 주변장치를 다룬다 = 정해진 주소에 값을 쓴다

**주변장치(peripheral)는 칩 안에 있는 작은 전용 회로**다. CPU가 코드로 흉내내는 기능이 아니라 CPU와 별개로 존재하는 물리적 회로이고, CPU는 설정값만 꽂고 손을 뗀다.

LED를 1초마다 깜빡이는 두 방법이 차이를 드러낸다.

```c
// A. CPU가 직접 — 840만 번 헛바퀴를 도는 동안 다른 일을 전혀 못 한다
while (1) { LED_ON(); for (volatile int i=0;i<8400000;i++); LED_OFF(); ... }

// B. 타이머 주변장치에 시킨다 — 숫자 셋을 쓰고 CPU는 자유
htim3.Init.Prescaler = 8399;
htim3.Init.Period    = 9999;
HAL_TIM_Base_Start_IT(&htim3);
```

이름의 유래는 메인프레임 시대다. **peripheral**은 그리스어 *peripherein*(*peri* 둘레 + *pherein* 나르다) = "둘레를 도는 것"으로, 프린터·천공카드 리더처럼 진짜 본체 바깥에 있던 것들을 가리켰다. MCU에서는 전부 같은 다이 안에 들어와 위치 관계가 깨졌지만 CPU가 주인이고 나머지가 명령받는다는 **위계**는 그대로라 이름만 남았다.

### 레지스터 — 회로에 달린 다이얼

세탁기로 비유하면 주변장치가 모터·펌프·히터이고, **레지스터**는 앞면의 다이얼과 버튼이다. MCU의 특이점은 그 다이얼이 **메모리 주소로 노출돼 있다**는 것 — 이게 **메모리 맵드 I/O**이고, 다이얼을 돌리는 방법은 그 주소에 숫자를 쓰는 것뿐이다.

```c
GPIOA->ODR |= (1 << 5);
```

| 조각 | 실제 의미 |
|---|---|
| `GPIOA` | 주소 `0x4002 0000` (GPIOA 회로 블록의 시작 번지) |
| `->ODR` | 그 블록의 +0x14번째 칸 = Output Data Register → `0x4002 0014` |
| `(1 << 5)` | 비트 5번 자리에 1 (PA5 핀 담당) |
| `\|=` | 나머지 비트는 두고 5번만 1로 |

변수에 대입하는 문법인데 실제로는 **금속 핀의 전압이 3.3V가 된다.** `x = 1`은 SRAM을 바꾸지만 `GPIOA->ODR = 1`은 물리적 결과를 낸다 — 파이썬만 하다 오면 반드시 걸리는 턱이다.

`R0`·`R12`·`LR`·`PC` 같은 **CPU 레지스터와는 다른 것**이다. CPU 레지스터는 코어 안의 계산용 임시 칸이라 주소가 없고 컴파일러가 알아서 쓰는 반면, 주변장치 레지스터는 주소가 있고 내가 직접 쓴다.

### 떠넘기기의 대가 — 병렬성

주변장치가 별도 회로라 CPU와 동시에 돈다. 제어 루프가 도는 시점에 칩 안에서는 CPU가 PID를 계산하는 동안 TIM1이 20kHz PWM을 출력하고, TIM2가 엔코더 펄스를 세고, TIM7이 1ms를 카운트하고, USART2가 로그를 송신한다 — 전부 CPU 관여 0. 멀티스레드가 아니라 회로가 물리적으로 여러 개라서 생기는 진짜 병렬이다. **일을 하드웨어에 떠넘겨 CPU를 비워두는 것**이 임베디드 설계의 기본 전략이다.

## 폴링과 인터럽트 — MCU 전용 개념이 아니다

"일이 생긴 걸 어떻게 아느냐"에 대한 답은 원래 둘뿐이고, 컴퓨팅 전 계층에 나온다. 파일이 생겼나 계속 확인하는 `while` 루프가 폴링, ROS2 `create_subscription` 콜백이 인터럽트의 소프트웨어 버전이다.

어원이 관계의 방향을 그대로 담고 있다.

- **poll** ← 고대 게르만어 *polle* = 머리(head). "머리 수를 센다" → 여론조사. 조사원이 집집마다 찾아가 묻듯 **내가 간다**.
- **interrupt** ← 라틴어 *inter*(사이에) + *rumpere*(부수다) = "사이를 깨부순다". rupture·bankrupt와 같은 뿌리로, 하던 흐름을 끊고 **쟤가 온다**.

### MCU에서 달라지는 것 — 인터럽트의 소유권

인터럽트 자체는 모든 CPU에 있다. 차이는 누가 받느냐다.

| | 리눅스/PC | MCU (bare-metal) |
|---|---|---|
| 받는 주체 | 커널 | **내 코드** |
| 내가 쓰는 것 | `epoll`, 콜백 | ISR 함수 그 자체 |
| 경로 | IRQ → 커널 핸들러 → 스케줄러 → 프로세스 깨움 | IRQ → NVIC → **내 함수로 점프** |
| 지연 | 수십 µs~ms, 가변 | 143ns, 고정 |

라즈베리파이에서도 인터럽트는 쉴 새 없이 발생하지만 커널이 다 먹고 내 코드에는 가공된 결과만 내려온다. MCU는 그 중간층이 아예 없다. **개념은 범용이고, 직접성이 MCU 고유다.**

폴링이 항상 열등한 것도 아니다. 이벤트가 아주 잦으면 인터럽트 진입 오버헤드가 오히려 손해라 고속 네트워크 드라이버는 일부러 폴링을 쓴다(리눅스 NAPI). 선택 기준은 이벤트 빈도와 지연 허용치다.

### IRQ · ISR · 제어 루프

```
타이머 하드웨어 ─IRQ(신호)→ NVIC ─점프→ TIM7_IRQHandler() ─안에서→ 제어 루프 1회분
```

| 약어 | 풀이 | 정체 |
|---|---|---|
| IRQ | Interrupt ReQuest | 전선을 타고 오는 **신호** |
| ISR | Interrupt Service Routine | 그 신호가 부르는 **함수** |
| 제어 루프 | control loop | 그 함수 안에서 도는 PID **한 사이클** |

제어 루프 코드에는 `while`이 없다. 반복하는 주체가 CPU의 루프문이 아니라 타이머 하드웨어이고, 코드에는 "한 번분"만 적혀 있기 때문이다.

```c
void TIM7_IRQHandler(void) {          // 타이머가 1ms마다 부른다
    int32_t pos = TIM2->CNT;
    float u = pid_update(target - pos);
    TIM1->CCR1 = (uint32_t)(u * ARR);
    TIM7->SR &= ~TIM_SR_UIF;
}
int main(void) {
    HAL_TIM_Base_Start_IT(&htim7);
    while (1) { }                     // 메인은 텅 비어 있다
}
```

"루프"라는 말도 두 갈래다. 프로그래밍의 loop는 코드 반복 실행이고, 제어공학의 loop는 **피드백 고리** — 목표에서 나간 신호가 모터를 거쳐 엔코더로 돌아오는 그 귀환선이 loop다. 어원(중세 영어 *loupe* = 밧줄의 고리)상으로는 제어 쪽이 원조이고, 프로그래밍이 "코드가 제자리로 돌아온다"로 빌려 갔다. 귀환선이 없으면 **open-loop**다 — 전자레인지가 음식이 데워졌는지 안 보고 3분만 돌리는 것처럼.

## 벡터 테이블 — 번호를 함수 주소로 바꾸는 배열

CPU는 `TIM7_IRQHandler`라는 **이름을 모른다.** 컴파일하면 이름은 사라지고 주소만 남는다. 그래서 "몇 번 신호가 오면 몇 번 칸을 읽고 거기 적힌 주소로 뛴다"는 약속표를 Flash 맨 앞에 둔다.

```
주소          인덱스  내용          의미
0x0800 0000    [0]   0x2002 0000   ← 스택 시작 주소 (함수가 아니다)
0x0800 0004    [1]   0x0800 0189   ← Reset_Handler
0x0800 0040   [16]   ...           ← IRQ 0 = WWDG
0x0800 011C   [71]   0x0800 0455   ← IRQ 55 = TIM7
```

TIM7이 신호를 보내면 CPU는 인덱스 $16+55=71$ 을 구해 `0x08000000 + 71×4 = 0x0800011C` 칸을 읽고 거기 적힌 주소로 점프한다. 곱셈 한 번, 메모리 읽기 한 번. 검색도 비교도 없다. **전화 단축번호와 같다** — 전화기는 "엄마"가 누군지 모르고 1번 칸에 저장된 번호로 걸 뿐이다.

**vector**는 라틴어 *vehere* = "나르다"에서 왔고 vehicle·convey와 뿌리가 같다. 여기서 뜻이 갈라져 수학·물리에서는 점을 나르는 양(크기+방향), 컴퓨터에서는 **제어 흐름을 나르는 주소**, 의학에서는 병원체를 나르는 매개체(모기 = malaria vector)가 됐다.

### 0번 칸이 함수가 아닌 이유

리셋 순간 Cortex-M이 실행하는 진짜 첫 동작이 이 두 줄이다.

```
1. MSP ← 메모리[0x08000000]   (스택을 어디다 쌓을지)
2. PC  ← 메모리[0x08000004]   (Reset_Handler로 점프)
```

x86이 정해진 주소로 점프만 하는 것과 달리 ARM은 스택부터 세운다. C 함수 호출은 스택이 먼저 있어야 가능하므로, **하드웨어가 C 언어를 배려해** 어셈블리 부트 코드를 최소화한 설계다.

### weak 심볼과 침묵하는 오타

`startup_stm32f446retx.s`에 테이블 실체가 있다.

```assembly
g_pfnVectors:
  .word  _estack            /* [0] 스택 top */
  .word  Reset_Handler      /* [1] */
  .word  TIM7_IRQHandler    /* [71] */
...
.weak  TIM7_IRQHandler
.thumb_set TIM7_IRQHandler, Default_Handler
```

**weak(약한 심볼)** 은 "기본값을 넣어둘 테니 누가 같은 이름으로 진짜 함수를 만들면 그걸 써라"는 뜻이다. 그래서 아무 `.c` 파일에나 `void TIM7_IRQHandler(void) {...}`를 쓰면 링커가 71번 칸을 그 함수로 바꿔 끼운다 — 등록 코드가 따로 필요 없는 이유다.

함정은 여기서 나온다. 이름을 `TIM7_IRQhandler`로 오타 내면 컴파일도 링크도 성공하고 경고 한 줄 없이 ISR만 안 불린다(71번 칸에 무한 루프인 `Default_Handler`가 남는다). 제어 루프가 통째로 안 도는데 에러가 없다. **ISR 이름은 손으로 치지 말고 startup 파일에서 복사한다.**

### 배열이라서 결정적이다

리스트 순회나 if-else 체인은 몇 번째냐에 따라 시간이 달라지지만, **배열 인덱싱은 주소 계산 1회 + 읽기 1회로 항상 같다.** 55번이든 3번이든 걸리는 사이클이 동일하고, 이 자료구조 선택 하나가 "12사이클 = 143ns 고정"이라는 실시간성을 만든다.

같은 "식별자 → 함수 포인터" 구조는 위로 갈수록 이름만 바뀐다 — C++ vtable(함수 인덱스 → 구현 주소), 파이썬 dict 디스패치, ROS2 콜백 등록(토픽 이름 → 콜백), URL 라우팅. 벡터 테이블은 그중 가장 원시적이고 빠른 버전으로, 키가 정수이고 테이블이 고정 주소에 있으며 조회를 하드웨어가 한다.

덧붙여 `VTOR` 레지스터(`0xE000ED08`)에 다른 주소를 쓰면 테이블 위치를 옮길 수 있다. 부트로더가 자기 테이블로 떴다가 펌웨어를 검사한 뒤 VTOR을 펌웨어 테이블로 옮기고 점프하는 식으로, 드론 펌웨어 OTA 업데이트가 이 구조다.
